Broodline.UI does not reference Broodline.Sim

A screen that can reach into simulation state will eventually compute something from it, and that computation is a game rule living in the client. The only path from simulation to interface is View.

Broodline.View renders; it never decides

Damage numbers, breach diagnoses and outcomes come from the engine's own output. If the view needs a number the engine does not expose, the engine gains an accessor — the view never derives it.

§2 · The sim-to-render boundary

The engine runs at a fixed 30 Hz. Rendering does not. View owns an accumulator, steps the engine as many times as elapsed time allows, and interpolates between the last two snapshots.

  • Two snapshots are retained — interpolation needs both.
  • Input is captured at a tick boundary: a Rally tap records the tick index, never a timestamp.
  • A dropped frame never drops a tick. Skipping ticks produces a run the server will not reproduce, and the player loses a wave they won.

§9 · Scenes and navigation
  • One persistent root scene, everything else additive. The root holds the composition root, the network layer, the tab bar and the top bar with Splice Charges always visible.
  • Wave Defense loads additively and unloads on exit — the only 3D scene, and the only one with a per-frame budget worth defending.
  • Five tabs: Map · Ark · Splice · Lab · Allies. No Store tab. The bar is a pure function of campaign progress and Geneticist Tier — nothing stored, nothing to lose on reinstall; thresholds live in the config bundle.
  • Bottom sheets overlay, they don't push. The Codex opens from every trait pip in the app; a navigation destination would put it in every back stack.
  • One replay screen. Outcome and the three-boolean breach diagnosis are always primary; Watch is an action that appears only when the engine version matches. Scrubbing is a full re-run — roughly 20 ms, so nobody notices.
§3–6 · Budgets

The floor is set by the cheap devices

Reference device: A14 with 4 GB — iPhone 12 and its variants, iPad Air 4, iPad 10th gen. Changed from A13 / 3 GB on 2026-09-14: no A13 hardware was available to measure on. Dropping that band is a revenue decision, taken knowingly.

60/30fps target and fallback; worst frame carries a tick and a render in 16.6 ms
600MBpeak. iOS terminates on memory pressure without a log worth reading
<1msfor the engine. Rendering owns essentially the whole budget
The degradation ladder — decided in advance
Under 40
Full fidelity — individual skinned meshes, full VFX
40–70
Identical raider types collapse to instanced rendering; hit VFX pooled and capped
Over 70
Animation rate halves for non-foreground entities; death VFX becomes one shared effect
Still short
Drop to 30 fps for the remainder of the wave. Last rung, because it is the most visible — and it latches, because a frame rate that hunts reads worse than either

The ladder keys off the engine's deterministic entity count, so two players watching the same replay see the same fidelity. Degradation touches rendering only; it can never touch SimState.

Content is fetched ahead of need, never at the moment of need — prefetch on the map, on wave select, on idle. A failed fetch degrades and explains; it never blocks on a spinner. The first hour never depends on the network.

§4 · Phase 0 gate
Wave 44, on a real A14 — real meshes still owed

Wave 44 and five of chapter 8's waves put close to a hundred entities on the board — sixty Skirmishers, three Broods becoming thirty-nine, five creatures. Measured at both 60 and 30 fps and against the 600 MB ceiling.

It was scheduled in Phase 1 alongside the rig proof, and for the same reason — though the two were split on 2026-09-14, this proof delivered and the rig proof moved to the art track: it can invalidate an assumption everything downstream is built on. If a hundred skinned meshes cannot hold 60 fps the answer is a rendering-strategy change — impostors, baked vertex animation, fewer unique bodies — and that changes the art budget.

Two things the engine must supply: identical entities instanced, not individually animated, and a per-tick entity count, so the render layer degrades before it drops frames.

§5 · Creatures are assembled, not authored

A species body, up to two trait attachments on named sockets, an Instinct marker. Six species × twelve traits × two slots is far too many combinations to author.

  • Assemblies are cached by (species, traitA, traitB) — the roster shows dozens of cards.
  • Attachments are individually addressable, so a new trait part ships as content, not an app update.
  • The creature card is a 2D render of the same assembly. A second representation is how the roster and the battlefield end up disagreeing about what a player owns.

§11

Sixteen guardrails

If a change breaks one of these, it is not a change — it is a different architecture. Pin this half of the sheet at eye level.

01  Broodline.UI never references Broodline.Sim
02  Broodline.View renders simulation output and never derives it
03  A dropped frame never drops a simulation tick
04  Rendering degradation keys off the engine's deterministic entity count and never touches SimState
05  Input is recorded at a tick index, never a timestamp
06  The client is a cache with an outbox and is never a source of truth
07  Server-authoritative values are cached for display only and are never operated on
08  Idempotency keys are generated when the action is taken, not when it is sent
09  The first hour ships in the binary and never depends on the network
10  A failed content fetch degrades and explains; it never blocks on a spinner
11  Creature assemblies are cached by (species, traitA, traitB)
12  The probability table renders published odds and never computes them
13  Layout is safe-area driven with no fixed pixel positions, and declares a minimum window size
14  The frame-rate degradation rung latches for the wave and never oscillates
15  The first hour ships four species; nothing in it waits on a download
16  Tab reveal is derived from progression and stored nowhere
