C. THE DEPLOY AND THE SMOKE LOOP - BLOCKED, AND NOT ON A DECISION
===============================================================================
Task 3 could not run. This is the one item here that is blocked on a SECRET
rather than on an Editor.

WHAT WAS MEASURED, 2026-09-22:

  - `gcloud run services list --project broodline-508416` returns ZERO
    services, in every region. `gcloud run services describe broodline-api`
    answers "Cannot find service". The Cloud Run Admin API is enabled and the
    account has access, so this is an empty list, not a permissions error.
  - `POST $API_URL/v1/wave/abandon` returns 404 - but so does
    `POST /v1/wave/start`, and so does `GET /`. All three return GOOGLE'S OWN
    404 page, not the app's. The brief's "401, not 404" check cannot
    distinguish anything while nothing is serving.
  - `terraform output -raw api_url` still prints a URL. THE STATE IS STALE:
    it lists `google_cloud_run_v2_service.api` and `.sim` as existing.
  - Cloud SQL `broodline-main` IS RUNNING (POSTGRES_16, db-f1-micro). That is
    what is billing. NOTHING WAS TORN DOWN by Task 20.
  - `implementation/scripts/smoke-loop.sh:18-21` already says, in its own
    header: "NEVER RUN. Nothing is deployed as this is written ... this
    script has been parsed, not executed, and no line below has ever answered
    against a live stack."

  So the addendum's premise - "The stack is up; the new route is not on it
  until the api image is rebuilt" - is refuted. The api and sim services do
  not exist at all. This is not a stale revision; it is a missing service.

WHY AN AGENT DID NOT PROCEED:

  1. `deploy.sh` requires `TF_VAR_db_password` and refuses without it. That
     value is the live `broodline_app` Postgres role password. Inventing one
     ROTATES the password on a running database; the correct one exists only
     in the user's password manager (and in Secret Manager, which an agent
     should not be reading plaintext credentials out of).
  2. `smoke-loop.sh` separately needs `DATABASE_URL` as an OWNER-role
     connection through the Cloud SQL Auth Proxy - a second credential.
  3. `terraform apply` here would not push a revision. It would RECREATE two
     deleted Cloud Run services. That is materially larger than the action
     that was authorised, and it changes what bills.

  Per the brief: "If the deploy fails, stop and report - do not improvise
  around it, and do not tear anything down." Nothing was torn down and
  `smoke-loop.ts` was NOT edited, because the brief gates that edit on a 401
  that cannot be obtained.

WHAT THE HUMAN DOES:

    export PROJECT_ID=broodline-508416
    export TF_VAR_db_password='<the broodline_app role password>'
    ./implementation/scripts/deploy.sh

  Then confirm the route exists before touching the smoke loop:

    API_URL="$(terraform -chdir=infra/terraform output -raw api_url)"
    curl -s -o /dev/null -w '%{http_code}\n' -X POST "$API_URL/v1/wave/abandon"
    # 401 (requireSession), NOT 404, and NOT Google's 404 page

  THE ROUTE DOES EXIST IN CODE and its contract matches Task 3's step
  exactly - `services/api/src/routes/wave.ts:863`, declared at
  `services/api/src/openapi.ts:102`. It answers `{settled: true}` on the
  first call and `{settled: false}` on a repeat (the `AND settled_at IS NULL`
  no-op), and `requireSession` is what makes an unauthenticated POST a 401.
  It has never been executed against a live stack by anything.

  Then add Task 3 Step 2's block to `implementation/scripts/smoke-loop.ts`
  (the brief has it verbatim) and run:

    bash implementation/scripts/smoke-loop.sh 2>&1 | tail -30

  Expect the new step's tick, the later replayed wave 1 still winning,
  [A]-[C] passing, and a final PASS. Abandon pays nothing, so the ledger
  expectations do not change.

  If the api revision fails to start with a generic "container failed to
  start", read `deploy.sh`'s PREREQUISITES block first - that message is what
  an unresolvable JWT_SECRET looks like. The secret currently HAS one enabled
  version, so this should not bite, but the message is misleading enough to
  be worth naming.
