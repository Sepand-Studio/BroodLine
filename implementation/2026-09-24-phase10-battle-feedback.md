# Phase 10 — live battlefield feedback source pass

The production wave now observes completed simulation ticks through `View/PresentationCues.cs`, the observer previously used only by the Frontier proof. `WaveRunner` advances its snapshot pair and delivers cues on each tick, including catch-up ticks. `WaveView` applies attack and hit poses and shows short pooled ground pulses for attacks, damage, chill, defeat, breach and Rally. The HUD uses a separate 18-label pool for floating text; its labels ignore pointer input, so only the existing pause and speed controls can intercept a Rally tap. Both pools reuse their entries under bursts. Pausing freezes them and speed controls their lifetime. The cue observer only reads the simulation; engine, replay and outcome code are unchanged.

The combat source check compiled the moved observer with the real engine and passed 120 wave/formation combinations with identical direct and observed hashes, exact damage/defeat/breach totals and no duplicate cues. The token and silent-drop gates passed, and changed C# files had no Roslyn syntax diagnostics. New EditMode tests cover the live pool bounds, HUD pointer behavior and hash neutrality; they are staged for the deferred Unity run on the user's Unity machine. Real lighting, pulse visibility at all portrait sizes, animation transitions and packaged-player performance remain for that final validation pass.
