# Implementation

Task plans and their outputs. Design and architecture live in `specs/`.

- `2026-09-08-phase0-entity-count-proof.md` — the render-budget proof that
  briefs the rig proof commission.
- `2026-09-09-phase1-engine-foundations.md` — the deterministic simulation core.
- `2026-09-10-phase2-combat-engine.md` — the combat engine vertical slice.
- `2026-09-10-phase3-unity-client.md` — the renderer, Rally, and the replay
  format.
- `results/` — benchmark output. Logs and test XML are gitignored: they are
  regenerated by re-running a script. Three kinds of file are tracked instead,
  because re-running does not reproduce them:

  | Tracked | Why it cannot be regenerated |
  |---|---|
  | `entity-budget-*.csv` | Needs a particular physical device, off charge, for half an hour. The measured evidence behind the render budget |
  | `editor-replay.bin` / `-outcome.txt` | Needs a human to play wave 6 in the Editor and tap once. Phase 3's round-trip evidence at every dimension except IL2CPP and the device — `EditorReplayTests` re-simulates it on every run |
  | `device-replay.bin` / `-outcome.txt` | Needs the physical device. Phase 3's done-when. `DeviceReplayTests` skips loudly until it exists |

  Findings are still promoted into the plan document itself; these files are
  the provenance behind them, not a substitute for reading them.
