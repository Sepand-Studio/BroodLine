# Implementation

Task plans and their outputs. Design and architecture live in `specs/`.

- `2026-09-08-phase0-entity-count-proof.md` — the render-budget proof that
  briefs the rig proof commission. **Signed off 2026-09-14**, by changing the
  reference device from A13 / 3 GB to **A14 / 4 GB** rather than by obtaining an
  A13: none was available. The margin that covered the gap was withdrawn with
  it, so the budget is the measured **10000 triangles**, not 7000. Two things
  survive the sign-off and are not waived — the re-run of this harness against
  real delivered meshes, and the rig proof itself, which moved to the art track
  because it is blocked on a commission rather than on engineering. Both now
  live in `specs/broodline_rig_proof.md` §8.3 and gate production species.
- `2026-09-09-phase1-engine-foundations.md` — the deterministic simulation core.
- `2026-09-10-phase2-combat-engine.md` — the combat engine vertical slice.
- `2026-09-10-phase3-unity-client.md` — the renderer, Rally, and the replay
  format.
- `2026-09-11-phase4-backend-spine.md` — the backend spine: identity, the
  ledger, the config bundle, and the first Cloud Run service.
- `2026-09-11-phase4-followups.md` — what Phase 4's execution found and chose
  not to fix. **Read it before re-deciding anything it names**: three of the
  defects it lists as owed were fixed after it was written and nothing re-read
  it, so Phase 5 nearly re-fixed them.
- `2026-09-13-phase5-validation.md` — validation: the `sim` service,
  server-issued seeds, submit-and-verify, replays to GCS, and the adversarial
  suite as the phase gate. Tasks 11 (GCP) and 12's deployed clauses are held.
- `2026-09-14-phase5-remediation.md` — the seven-task close-out of Phase 5's
  fifteen deferred minors, the adversarial gate, and the whole-branch review.
- `2026-09-13-phase5-followups.md` — the durable copy of Phase 5's findings:
  what is knowingly open, what is owed against work that does not exist yet,
  what is undiagnosed, and the eleven assertions this phase caught being green
  while proving nothing. The phase's reasoning lives here and nowhere else.
- `results/` — benchmark output. Logs and test XML are gitignored: they are
  regenerated by re-running a script. Four kinds of file are tracked instead:

  | Tracked | Why it is tracked |
  |---|---|
  | `entity-budget-*.csv` | Needs a particular physical device, off charge, for half an hour. The measured evidence behind the render budget |
  | `editor-replay.bin` / `-outcome.txt` | Needs a human to play wave 6 in the Editor and tap once. Phase 3's round-trip evidence at every dimension except IL2CPP and the device — `EditorReplayTests` re-simulates it on every run |
  | `device-replay.bin` / `-outcome.txt` | Needs the physical device. Phase 3's done-when. **Currently superseded**: captured under engine `0.1.0` against a `0.2.0` engine, so both round-trip tests bail before their asserts and report *passed*. There is no `Skip` anywhere in the solution — a Skip-on-missing-artifact attribute once inverted this very gate — so no count reports it. The marker is `TheDeviceRunIsSupersededAndIsNotReSimulated`, whose **green** is the statement that the round-trip is dark and whose red is the instruction to restore the hash comparison |
  | `phase5-test-baseline.txt` | Reproducible, unlike the three above, and tracked for the opposite reason: it is the machine-diffable replacement for counts written into sentences. Phase 4 recorded "71" in a paragraph, the real number was 74, and nobody noticed for a phase. **It supersedes any count typed into prose anywhere in `implementation/` or `specs/`** |

  Findings are still promoted into the plan document itself; these files are
  the provenance behind them, not a substitute for reading them.
